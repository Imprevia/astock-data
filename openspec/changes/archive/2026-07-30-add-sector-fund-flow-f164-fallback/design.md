## Context

`get_sector_fund_flow_history` 当前按板块调用东方财富 push2his，成功时返回带日期的逐日主力净流入。push2his 失败后，同花顺行业 K 线只能返回 `date`、`close`、`amount` 和 `pct_change`，不能证明主力净流入；SQLite 也只能回退到此前成功写入的逐日数据。东方财富板块资金页的 `getbkzj` 接口可以通过一次请求返回官方行业范围 `m:90+s:4` 的 `f164`，其语义是当前滚动五个交易日的主力净流入累计值，但不带逐日明细或可验证的数据日期。

该变更跨越客户端、服务编排、结果模型和公共门面。数据包必须继续只返回事实数据，并保持所有东方财富 URL 位于 `astock_data/clients/eastmoney.py` 的单一请求边界内。

## Goals / Non-Goals

**Goals:**

- 在当前日期且请求窗口恰为五日时，用一次 `f164` 批量请求补齐 push2his 缺失板块的五日累计主力净流入。
- 保留 push2his 逐日序列，确保下游仍可计算流入正天数。
- 在模型中明确区分真实逐日序列和仅有五日累计值的部分结果。
- 阻止当前滚动值污染历史日期报告，并使来源降级可观察、可测试。

**Non-Goals:**

- 不从 `f164` 推导或伪造五个交易日的逐日值。
- 不把同花顺成交额、收盘价或涨跌幅解释为主力净流入。
- 不改变行业评分、投资判断或报告展示逻辑。
- 不为任意 `days` 参数模拟五日以外的累计值。

## Decisions

### 1. 使用官方行业范围和专用客户端解析器

客户端固定调用 `data.eastmoney.com/dataapi/bkzj/getbkzj`，参数为 `key=f164` 和 `code=m:90+s:4`。该范围是东方财富当前行业资金页实际使用的 128 个行业板块范围；`t:3` 是概念板块，`t:2` 会混入多级行业。解析器只输出板块代码、名称和可空的五日累计主力净流入，原始单位保持为元。

备选方案是复用 push2 `clist` 的 `f62` 并在本地累积。该方案需要连续五个交易日稳定落盘，不能立即补齐已有缺口，因此不作为本次主方案。

### 2. `f164` 是受限的批量降级，而不是逐日历史替代品

push2his 继续负责逐日序列。服务在某些板块缺少有效逐日记录时，至多触发一次共享的 `f164` 批量请求，并按板块代码填充五日累计值。只有以下条件同时满足时才允许请求 `f164`：

- `days == 5`；
- 目标日期等于本地当前日期；
- 至少一个请求板块缺少有效 push2his 逐日记录。

显式历史日期、周末回看上一交易日或任意非五日窗口均跳过 `f164`，因为接口没有响应日期，无法证明滚动窗口与目标日期一致。此处选择保守缺失而不是日期错配。

### 3. 新增独立的五日累计映射

`SectorFundFlowHistoryResult` 新增 `five_day_main_net_inflow_by_code` 可空映射。`history_by_code` 继续只承载上游返回的记录，不会为了适配累计值生成虚假的单日或五日记录。

- push2his 成功且 `days == 5`：五日累计映射可由有效逐日 `main_net_inflow` 求和得到。
- push2his 缺失且 `f164` 命中：累计映射写入 `f164` 值，逐日序列保持空。
- 同花顺仅返回行情字段：不得写入五日累计映射，也不得生成 `main_net_inflow=0`。
- 所有资金来源均缺失：两个结果位置都保持空，并输出警告。

选择独立字段而不是把累计值塞入 `history_by_code`，是为了让消费者通过数据形状直接区分完整与部分结果，并保持现有逐日字段向后兼容。

### 4. 批量请求、缓存和警告共享

并发板块请求共享同一个惰性 `f164` 结果；无论缺失多少板块，每次服务调用最多访问一次该接口。成功载荷写入按目标日期隔离的结构化缓存，但缓存不得跨日期回退后冒充当前滚动窗口。警告按板块说明“仅五日累计可用、无逐日序列/正天数”，公共 API、CLI 和 MCP 通过模型序列化自然透传。

### 5. 保留同花顺兼容数据但收紧资金语义

现有同花顺行业 K 线仍可作为兼容降级记录返回，以避免无关消费者发生突变；但服务和测试明确禁止将其 `amount` 或缺失字段映射为主力净流入。下游若需要资金持续性，必须只使用含 `main_net_inflow` 的逐日记录或新增的五日累计映射。

## Risks / Trade-offs

- [东方财富未公开接口可能变更字段或行业范围] → 使用严格解析、空载荷降级、离线契约测试和来源警告，不把解析失败转换为零值。
- [`f164` 不带日期，周末也可能对应最近交易日] → 仅允许目标日期等于本地当前日期；宁可周末缺失，也不污染历史报告。
- [新增字段增加公共契约表面积] → 保持原字段不变，新增字段使用默认空映射，并同步 API/CLI/MCP 契约测试。
- [部分板块代码不在 `s:4` 范围] → 仅按代码精确匹配，未覆盖板块继续现有降级链并输出警告，不做名称模糊匹配。
- [并发线程重复触发批量请求] → 使用调用内共享状态与锁保证至多一次请求。

## Migration Plan

1. 先以失败测试锁定客户端字段解析、单次批量请求、五日窗口限制和历史日期禁止调用。
2. 增加客户端与模型字段，再接入服务编排和结构化缓存。
3. 更新 API、CLI、MCP 契约及数据源文档，运行完整测试和文档门禁。
4. 以可编辑安装方式提供给 `daily-review`，再实施消费者变更。

回滚时可以停止填充新增字段并移除 `f164` 编排；原 `history_by_code` 契约未改变，下游仍可回到原有逐日行为。

## Open Questions

无。若未来能从上游获得可验证的交易日期，再单独评估周末和历史日期使用 `f164` 的放宽条件。
